# 0013. Формат файла проекта

- **Статус:** Accepted
- **Дата:** 2026-11-04

## Контекст

Пользователь настраивает десятки параметров (высоты, допуски, фаски, порядок слоёв) и хочет вернуться к работе
позже. Нужно хранить: исходный SVG, настройки элементов, глобальные настройки.

Варианты: хранить разобранное дерево (`SvgDocument`) целиком или только исходный текст SVG. Дерево содержит
флэттенные контуры — это десятки тысяч чисел, а его структура зависит от парсера.

## Решение

Файл `*.svg23d.json` содержит:

- `app: "svg23d"`, `version` (целое, сейчас 1);
- `fileName`, `source` — исходный SVG **как текст**;
- `global` — глобальные настройки;
- `settings` — `Record<nodeId, NodeSettings>`.

При открытии: файл валидируется → `source` заново парсится → `settings` накладываются.
Идентификаторы узлов стабильны (собственный `id` элемента либо путь вида `s0.2.1`), поэтому настройки
находят свои узлы после повторного парсинга.

Версия выше текущей — ошибка «не поддерживается»; ниже — точка для будущих миграций (`migrateProjectFile`).

## Последствия

- Файл компактный и переживает улучшения парсера (пересчёт контуров с новым качеством).
- Настройки не привязаны к геометрии — при изменении SVG настройки «съезжают» только если поменялись
  id/структура; в этом случае лишние записи просто игнорируются (безопасно).
- Исходник дублируется в файле проекта (обычно десятки КБ) — приемлемая плата за автономность.
- Формат человекочитаемый: diff в git и ручная правка возможны.

## Когда пересматривать

Если появятся тяжёлые растровые вложения или потребуется хранить несколько вариантов сборки в одном файле —
ввести ссылки на внешние ресурсы и контейнер (zip) вместо JSON.
