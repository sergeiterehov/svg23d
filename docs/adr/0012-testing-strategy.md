# 0012. Тестирование: инварианты геометрии вместо скриншотов

- **Статус:** Accepted
- **Дата:** 2026-11-04

## Контекст

Главный риск проекта — «модель выглядит правильно, но печатается неправильно»: самопересечения, дырки,
неверные зазоры, сломанные фаски. Скриншотные тесты 3D-сцены хрупкие и не ловят такие дефекты.
При этом WASM-движок даёт точные числовые характеристики (`volume()`, `boundingBox()`, `numTri()`, `genus`).

## Решение

Три уровня:

1. **Unit-тесты чистых функций** (vitest, без браузера): трансформы, парсер path (включая дуги), flatten
   (площадь круга, длина кривой), разрешение стилей, наследование настроек, раскладка z-диапазонов,
   писатели STL/3MF (структура архива, XML, размер файла).
2. **Геометрические инварианты** на Manifold — основная защита:
   - квадрат 100×100, `extrude` 2 мм → объём 20 000 мм³ ±0.1 %;
   - фаска 1 мм по всему периметру → объём ≈ 19 800 мм³ ±1 % (снятый объём = `c²/2 × perimeter`);
   - `offset(+d)` → прирост площади ≈ `perimeter × d` ±2 %;
   - гнездо: вырезанная площадь = площадь верхнего листа + `clearance × perimeter`;
   - каждая деталь: `genus` и число компонент соответствуют ожиданию, меш замкнут.
3. **Golden-фикстура `sample.svg`**: число листьев/контуров, суммарная площадь, bbox, объём каждой детали.
   Снапшот числовой (не картинка), обновляется осознанно.

E2E (Playwright) — только smoke в M8: загрузка файла → появление дерева → экспорт → файл скачался и не пустой.

## Последствия

- Тесты быстрые (ядро без DOM и без WASM там, где можно).
- Регрессии геометрии ловятся числом, а не глазами.
- Требуется ручная проверка в слайсере как финальный критерий (её нельзя заменить тестами).

## Когда пересматривать

Если понадобятся визуальные регрессии — добавить скриншоты 2D-превью (canvas) как дополнительный слой,
но не как замену инвариантам.
