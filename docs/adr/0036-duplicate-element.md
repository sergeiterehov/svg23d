# 0036. Дублирование элемента: копия в оверлее, выше оригинала по списку и по высоте

- **Статус:** Accepted
- **Дата:** 2026-11-05

## Контекст

Копию элемента приходится делать вручную: пересоздать фигуру нельзя, а в дереве
нет даже «вставить». Между тем это обычное действие: второй слой того же контура,
ещё одна деталь из той же формы.

Геометрию в проекте хранит исходный SVG, а структурные правки — оверлей
(ADR-0026): группы, перемещения, переименования и удаления. Оверлей умеет
описывать только то, что уже есть в документе или создано пустым (`groups`), —
скопировать узел он не мог.

Отдельная сложность в модели: копия «в том же месте» в этом инструменте
небезобидна. Деталь вырезает гнездо в каждой детали, которая лежит ниже и
пересекается по Z (ADR-0005), поэтому две одинаковые детали на одной высоте
полностью съедают друг друга: обе становятся пустыми.

## Рассмотренные варианты

1. **Запекать копию в исходный SVG при импорте.** Ломает главное правило проекта:
   `source` остаётся ровно тем, что загрузил пользователь, иначе переразбор при
   смене качества кривых (ADR-0030) теряет правки.
2. **Копия — запись в оверлее (выбрано).** `copies` описывает, что клонировать и
   куда положить; дерево собирается на лету, файл проекта остаётся компактным.
3. **Копия на той же высоте, без сдвига.** Просто, но в модели обе детали
   исчезают (см. выше) — пользователь увидит предупреждение «полностью
   перекрыт» вместо второй детали.

## Решение

- В оверлее появился список `copies: { id, sourceId, parentId }[]`.
  `applyTreeEdit` клонирует поддерево источника под новыми id (`<id>` и
  `<id>.<n>` для потомков) и вставляет копию сразу за источником в детях
  родителя. Источником может быть и предыдущая копия — копия копии работает.
- Id копии — `<id источника>-2`, `-3`, …; занятые id (включая удалённые копии)
  не переиспользуются, чтобы «воскресшая» копия не появилась на месте удалённой.
- Копия сохраняет имя (вместе с переименованием из оверлея), состав и флаг
  объединения: копия объединения — тоже объединение. Настройки источника
  (высоты, фаска, допуск, цвет, порядок детей) переносятся на копию; `childOrder`
  переписывается по карте id.
- **Копия — это новый слой.** Её диапазон высот — `[zTo источника; zTo +
толщина]`, а собственные высоты потомков сдвигаются на ту же величину. Строка
  копии встаёт прямо над оригиналом, и в модели она тоже оказывается над ним:
  список и стопка говорят одно и то же.
- Действие живёт в контекстном меню строки («Дублировать», `⌘D`) и в
  `duplicateSelected`; выделение переходит на копию, отмена — один шаг.
- Копия части объединения нового тела не создаёт: она добавляется в то же тело
  (часть внутри объединения — не отдельный лист).

## Последствия

- Исходный SVG не меняется, поэтому файл проекта почти не растёт: копия — это три
  поля на весь поддерево.
- Удаление копии не трогает оригинал, удаление оригинала не трогает копию:
  у копии свои id и свои настройки.
- В шапке инспектора видны технические id (`s0.2-2`) — так же, как у остальных
  элементов; на работу это не влияет.
- Дублирование меняет модель (новая деталь в стопке), поэтому это обычный шаг
  истории с пересборкой.
