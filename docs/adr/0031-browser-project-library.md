# 0031. Библиотека проектов в браузере

- **Статус:** Accepted
- **Дата:** 2026-11-04

## Контекст

Проект жил только в памяти вкладки: перезагрузка страницы стирала всё, что пользователь настроил, а
единственным способом что-то сохранить было скачать `.svg23d.json` вручную. Нужно, чтобы работа
переживала перезагрузку сама, чтобы можно было держать несколько проектов и переключаться между
ними, и чтобы список примеров не занимал место в статусбаре.

## Рассмотренные варианты

1. **`localStorage`.** Синхронно и просто, но квота ~5 МБ строк: один SVG на несколько сотен
   килобайт плюс история — и запись начнёт падать. Ещё один минус — синхронные блокировки
   главного потока на больших строках.
2. **IndexedDB.** Асинхронно, квоты на порядки больше, хранит объекты как есть. Минус — старт
   становится асинхронным: приложение должно дождаться чтения, иначе сначала мигнёт пустой проект.
3. **Файлы через File System Access API.** Ближе к «настоящему» приложению, но требует выбора
   папки и поддержки не во всех браузерах; как основной механизм — перебор.

## Решение

- **Проекты — в IndexedDB** (`svg23d`, хранилище `projects`, ключ `id`). Запись — это файл проекта
  (`ProjectFile`) плюс метаданные библиотеки: `id` (guid), `name` (отображаемое имя), `createdAt`,
  `updatedAt`. Уникальность — по `id`: имена могут повторяться, guid — нет.
- **Настройки приложения — отдельно** (`localStorage`, ключ `svg23d:settings`): режим 2D/3D и вид
  (режим 2D, освещение, материал, проекция). Это свойство человека, а не артефакта, поэтому при
  открытии проекта они побеждают над `global.view`, сохранённым в проекте. Всё, что влияет на
  геометрию (размер, допуск, фаски, качество кривых), остаётся в проекте.
- **Последний проект** запоминается отдельным ключом `svg23d:last-project`. `bootstrap()` при
  старте читает библиотеку, применяет настройки и открывает последний проект (или самый свежий);
  до этого момента интерфейс показывает «Открываем последний проект…» — так пустой проект не
  мигает перед загрузкой.
- **Автосохранение.** Подписка на стор с задержкой 600 мс: правка настроек, дерева, переименование
  — это одна запись. Открытие проекта **не** считается правкой (меняется только `projectId`), а
  импорт сохраняется сразу, поэтому новый проект появляется в истории немедленно. `updatedAt`
  меняется только при настоящем редактировании.
- **Шапка:** имя проекта — кнопка с шевроном. Список отсортирован по `updatedAt` убыв., в строке —
  имя, метка «открыт», дата («сегодня, 14:32» / «вчера, …» / `04.11.2025`). Клик открывает проект
  (с задержкой 220 мс, чтобы двойной клик успевал начать переименование), двойной клик — инлайн-
  переименование, корзина удаляет после подтверждения. Удаление открытого проекта переключает на
  самый свежий из оставшихся или на пустой.
- **Импорт с занятым именем** спрашивает: открыть существующий проект или создать новый из файла.
  Имена не уникальны, так что «создать новый» просто добавляет ещё одну запись.
- **Скачивание остаётся** (кнопка с дискетой, `⌘S`): файл — единственная копия, не зависящая от
  браузера.
- Из статусбара убран список примеров: он нужен только на пустом проекте и живёт в блоке загрузки.

## Последствия

- Работа переживает перезагрузку и закрытие вкладки (запись при `beforeunload` и при скрытии
  вкладки — по возможности). Очистка данных сайта в браузере стирает историю: об этом стоит помнить,
  поэтому скачивание файла никуда не делось.
- Старт асинхронный: `hydrated` в сторе держит интерфейс до чтения IndexedDB. Если IndexedDB
  недоступна (приватный режим, запрет хранилища), приложение работает как раньше — просто без истории.
- Проект может быть большим: IndexedDB хранит и SVG-исходник, и настройки, поэтому истории не грозит
  квота `localStorage`.
- Дата последней правки — единственный признак «свежести»; порядок списка и подпись в строке
  считаются из неё, отдельного «времени открытия» нет.

## Когда пересматривать

Если понадобится синхронизация между устройствами или общий доступ — это уже серверное хранилище,
и `projectsDb` станет одним из двух провайдеров за общим интерфейсом.
