# 0026. Группировка, переименование, перемещение и удаление как оверлей над документом

- **Статус:** Accepted
- **Дата:** 2026-11-04

## Контекст

Дерево слоёв раньше показывало ровно то, что было в SVG: переставить элементы можно было только
стрелками (через `settings.childOrder`), а групп, переименований и удаления не было вовсе. Нужны все
четыре операции — и чтобы они были обратимыми, и чтобы переживали сохранение проекта.

Проект хранит **исходный SVG** (`.svg23d.json` → `source`), а разобранное дерево получается при
открытии. Если править дерево «на месте», то сохранение либо потеряет правки, либо придётся
сериализовать всё дерево с контурами (мегабайты) и потерять обещанную устойчивость к улучшениям
парсера (ADR-0013).

## Решение

Структурные правки — **оверлей** над разобранным документом (`src/core/model/treeEdit.ts`):

```ts
interface TreeEdit {
  names: Record<string, string>; // id → новое имя (в том числе у созданных групп)
  parents: Record<string, string>; // id → id родителя ('' = корень), только перемещённые
  groups: string[]; // созданные пользователем группы (их нет в SVG)
  removed: string[]; // удалённые узлы, вместе с поддеревом
}
```

- `applyTreeEdit(document, edit)` — чистая функция: клонирует дерево, выкидывает удалённое, создаёт
  группы, перевешивает узлы (с защитой от перемещения в собственного потомка и в фигуру), применяет
  имена, пересчитывает `depth` и `paintOrder`. **`hash` документа не меняется** — геометрия та же,
  поэтому камера не прыгает после группировки.
- Порядок соседей остаётся там, где уже был: `settings.childOrder` (его читают и солвер, и дерево).
  Группировка/перемещение заодно пишут `childOrder` нового родителя, чтобы группа встала на нужное
  место, а не в конец.
- Стор держит `baseDocument` (результат парсинга) и `project.tree`; `project.document` всегда равен
  `applyTreeEdit(base, tree)`. История (`past`/`future`) хранит снимки `{ settings, global, tree }`,
  поэтому отмена возвращает и структуру, и настройки одним шагом.
- В файл проекта добавляется `tree` (версия формата 2); старые файлы читаются как «правок нет».

### Группировка

Новая группа (`⌘G`, пункт «Сгруппировать выделенное» в меню «Инструменты») встаёт на место
**наименее вложенного и более верхнего** элемента выделения — это единственная позиция, при которой
стек остаётся предсказуемым, когда выделение разбросано по разным группам. Внутри группы элементы
идут в порядке отрисовки. Если в выделении есть и предок, и его потомок, потомок отбрасывается
(и не может «уехать» дважды).

### Перемещение, переименование, удаление

- **Перетаскивание**: верхняя треть строки — «над ней» (позже в порядке отрисовки), нижняя треть —
  «под ней», середина группы — «внутрь». Ряды отрисованы сверху вниз, поэтому «над строкой» = позже
  в порядке отрисовки; пересчёт делает `moveNode` в сторе.
- **Переименование**: двойной клик по строке, Enter — применить, Esc — отменить, пустое имя
  игнорируется.
- **Удаление**: `Delete`/`Backspace` или пункт «Удалить выделенное» в меню «Инструменты».

## Последствия

- Все четыре операции — один шаг отмены и сохраняются в проекте; исходный SVG не меняется, поэтому
  «открыть заново» всегда даёт исходную картинку.
- Стрелки ↑/↓ из дерева убраны: порядок меняется перетаскиванием (стрелки были единственным
  генератором `childOrder` и мешали свободному перемещению).
- Удалённые узлы остаются в `settings` — их настройки возвращаются вместе с отменой; на модель они
  не влияют, потому что узлов нет в дереве.
- Группировка меняет состав печатных деталей: детали по умолчанию — дети корня, поэтому объединённые
  элементы становятся одной деталью. Это осознанно: группа — единица печати.
- `contentBox` документа не пересчитывается: удаление части не должно масштабировать модель.
