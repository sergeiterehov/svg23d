# 0014. Обводка (stroke) превращается в отдельную геометрию

- **Статус:** Accepted
- **Дата:** 2026-11-04

## Контекст

Векторные редакторы часто отдают контур не заливкой, а обводкой (`stroke` + `stroke-width`), либо
используют обе: заливка внутри, обводка снаружи. Раньше мы такие элементы теряли: `fill: none` → элемент
пропускался с предупреждением, а `stroke` не влиял ни на что. На файле `samples/name.svg` (текст, залитый
обводкой 22 px) обводка просто исчезала.

Для печати обводка — это не «линия», а **область**: кольцо толщиной `stroke-width` вокруг контура.
Её нужно выдавить, и логично дать ей собственные высоту, допуск, цвет и место в порядке вырезания.

## Рассмотренные варианты

1. **Расширить path до площади** (наш выбор): разбить контур на отрезки, добавить по прямоугольнику на
   отрезок, по диску в вершину (стыки) и колпаки на концах, затем объединить всё через `CrossSection`.
   Работает только штатными 2D-операциями, устойчиво к самопересечениям, ширина масштабируется вместе с
   матрицей (обводка строится в локальных координатах).
2. **Offset открытого пути в Clipper2** — то, что делает SVG-рендеринг. Manifold не выставляет API
   открытых путей, а тащить второй движок ради этого нерационально.
3. **Растеризация в маску** — потеря точности и «лестницы», несовместимо с остальным конвейером.

## Решение

- `stroke` с шириной > 0 и видимым цветом превращается в многоугольники (`src/core/svg/stroke.ts`):
  прямоугольник на сегмент + диск в каждую вершину + колпак (`butt`/`round`/`square`) на концах открытых
  подпутей. Все многоугольники выдаются против часовой стрелки, объединение делает `CrossSection`
  с правилом NonZero.
- **Стыки всегда скруглённые**: для `round` это точное поведение, для `miter`/`bevel` — безопасный
  супермножество (скруглённый внешний угол). Для печати разница несущественна, а геометрия остаётся надёжной.
- Обводка становится **отдельным узлом** дерева с id `<id>#stroke` и именем `… · обводка`. Она идёт
  **после** заливки (порядок отрисовки SVG: сначала fill, потом stroke), поэтому может резать заливку,
  если они попадут в разные печатные детали.
- Цвет узла обводки — цвет `stroke`; `fill` внутри элемента сохраняет свой цвет.
- `stroke-dasharray` не поддержан (обводка будет сплошной) — предупреждение в панели.
- `mask`/`clip-path` по-прежнему не применяются: обводка видна целиком (предупреждение это сообщает).

## Последствия

- Элементы с `fill: none` + `stroke` больше не пропадают.
- Один элемент SVG может дать два элемента в дереве — это осознанно и позволяет задать им разные высоты.
- Идентификаторы стабильны (`#stroke`), поэтому настройки переживают повторный разбор файла.
- Больше полигонов: на `name.svg` модель выросла до ~17 тыс. треугольников — для печати это нормально,
  на расчёт влияет слабо (десятки миллисекунд).
- Обводка, заданная в единицах пользователя, корректно масштабируется вместе с моделью, потому что
  геометрия строится до применения матрицы.

## Когда пересматривать

- Понадобятся точные `miter`-стыки (например, для острых углов с большим miter-limit) — добавить
  расчёт пересечения смежных отрезков с падением на `bevel`.
- Понадобится поддержка `mask`/`clip-path` (в `name.svg` маска скрывает обводку под буквами) — делать
  отдельным решением: 2D-пересечение или вычитание уже есть, вопрос в семантике масок (яркость/альфа).
