# 0034. Публикация на GitHub Pages через Actions

- **Статус:** Accepted
- **Дата:** 2026-11-04

## Контекст

Приложение — статический бандл (React + three.js + WASM Manifold в Web Worker), которому нужен
только HTTP-сервер. Хочется дать ссылку, которая открывается у любого: без установки и сборки.
Репозиторий уже на GitHub (`sergeiterehov/svg23d`), поэтому напрашивается Pages.

Особенности, которые надо учесть:

- Pages отдаёт сайт из подпути `/svg23d/`, а дев-сервер работает из корня. Абсолютные
  `/assets/...` в бандле в таком случае ломаются.
- Геометрия считается в Web Worker'е, который подгружает `manifold.wasm` по URL из
  `?url`-импорта: и воркер, и WASM должны попасть в артефакт с правильными путями.
- Роутера нет: единственная страница, deep links и `404.html` не нужны.

## Рассмотренные варианты

1. **Коммитить `dist` в ветку `gh-pages` вручную.** Работает всегда, но добавляет шум в
   историю, требует помнить про сборку и легко забывается: сайт расходится с `main`.
2. **`gh-pages`-ветка, которую пушит локальный скрипт.** То же самое, плюс зависимость от
   машины разработчика.
3. **GitHub Actions: проверки → сборка → артефакт → Pages API (выбрано).** Сайт всегда
   собирается из `main`, `dist` не попадает в git, а упавшие тесты или типы не публикуются.

## Решение

- `vite.config.ts` получает `base = '/svg23d/'` **в production-режиме** и `/` во всех
  остальных: так работают и `npm run build`, и `npm run preview` (он тоже `mode: production`),
  и дев-сервер. Проверка идёт по `mode`, а не по `command`: `vite preview` — это `serve`,
  и по `command` он получал корневой base и не находил собственные ассеты.
- Подпуть — это имя репозитория. Переименование репозитория требует правки `PAGES_BASE`.
- `.github/workflows/deploy.yml` на push в `main` (и по кнопке `workflow_dispatch`):
  `npm ci` → `typecheck` → `lint` → `test` → `build` → `upload-pages-artifact` (`dist`) →
  `deploy-pages`. Права `pages: write` и `id-token: write`, один конкурентный запуск на
  группу `pages`, новый пуш отменяет предыдущий.
- `actions/configure-pages` вызывается с `enablement: true`: собственно включение Pages
  делает первый же прогон, ручных настроек в Settings не требуется.
- Ветка `gh-pages` и коммиты `dist` не используются — артефакт живёт только в прогоне.

## Последствия

- Сайт: `https://sergeiterehov.github.io/svg23d/`. Он обновляется на каждый пуш в `main`,
  но только если зелёные типы, линт и тесты — красный прогон не публикует ничего.
- Пути внутри бандла (`assets/*.js`, `assets/*.wasm`, воркер) относительны подпути, поэтому
  приложение работает и в подпапке, и локально через `npm run preview`.
- Проекты в библиотеке браузера (IndexedDB) привязаны к origin: на `github.io` своя
  библиотека, отдельная от `localhost`. Это ожидаемо: данные не «переезжают» между средами.
- Любая новая статика (шрифты, модели, WASM) должна попадать в бандл через импорт, иначе
  в артефакт она не попадёт.

## Когда пересматривать

Если понадобится свой домен или хостинг с серверной частью (например, чтобы делиться
проектами ссылкой) — Pages перестанет быть достаточным; тогда переезд на статический
хостинг с CDN или на сервер, а workflow останется только сборкой артефакта.
