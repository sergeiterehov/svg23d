# 0004. Приоритет вырезания = порядок отрисовки SVG + ручной порядок

- **Статус:** Accepted
- **Дата:** 2026-11-04

## Контекст

Когда два выдаленных элемента пересекаются, нужно решить, кто в кого «врезается». Пользователь формулирует это как
«элементы SVG на более верхнем слое вырезают свой объём из элементов на более нижних». В SVG нет явного Z-порядка:
он задаётся порядком элементов в документе (paint order — что нарисовано позже, то визуально выше).

Альтернативы: ориентироваться на диапазоны высот (`zFrom/zTo`) или только на ручной порядок в дереве.

## Рассмотренные варианты

1. **Paint order документа** — совпадает с тем, что пользователь видит в редакторе; ничего не нужно настраивать.
   Минус: порядок в векторном редакторе бывает случайным, а изменение порядка меняет геометрию.
2. **Только ручной порядок в дереве** — полный контроль, но пользователь обязан расставить всё вручную, а
   соответствие картинке теряется.
3. **По z-диапазонам (кто выше по Z)** — выглядит логично, но ломается при частичном перекрытии диапазонов
   (например, `0..3` и `2..5`: у обоих есть «высокая» часть) и не даёт ответа для одинаковых диапазонов.

## Решение

Базовый приоритет — **порядок отрисовки SVG** (документный порядок, с учётом вложенности групп: обход в глубину,
дети в порядке объявления). Поверх него — **ручное переупорядочивание в дереве** (drag & drop), которое сохраняется
в проекте как явный список и полностью замещает документный порядок для затронутого уровня.

Порядок фиксируется один раз при импорте (`ResolvedLeaf.order`) и дальше используется солвером.
В UI элементы показываются «сверху вниз» (первый в списке — самый верхний): список в дереве отрисован
в обратном порядке относительно paint order. Ручное изменение — кнопками ↑/↓ на строке, они меняют
место узла только среди его братьев и сохраняются как `childOrder` у родителя (ADR-0013).

Выбраны именно стрелки, а не drag & drop: они доступны с клавиатуры, не ломают вложенность при случайном
перетаскивании и дают очевидный шаг изменения (вверх/вниз на одну позицию).

## Последствия

- Результат совпадает с ожиданием пользователя «что нарисовано сверху, то и вырезает».
- Перестановка в дереве — значимая операция: нужна поддержка undo/redo (M7).
- Солвер не зависит от того, откуда взялся порядок: ему передаётся уже упорядоченный список листьев.
- Если порядок в SVG нелогичен, пользователь исправляет его в дереве, не редактируя исходник.

## Когда пересматривать

Если появится запрос «вырезание по Z» (например, элементы с непересекающимися Z, но пересекающиеся по XY) —
добавить режим приоритета как настройку проекта, оставив paint order дефолтом.
