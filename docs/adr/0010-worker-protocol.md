# 0010. Геометрия в Web Worker: протокол job/result с отменой

- **Статус:** Accepted
- **Дата:** 2026-11-04

## Контекст

Пересчёт модели — это WASM-инициализация Manifold (десятки мс), flatten контуров, десятки 2D-операций offset и
3D-булевых операций. На среднем SVG это единицы–десятки миллисекунд, на сложных — сотни. Всё это блокирует
главный поток: UI (орбита камеры, ввод в поля) начинает дёргаться.

При этом параметры меняются интерактивно (пользователь тянет число высоты), то есть запросы идут пачками и
устаревшие результаты не нужны.

## Рассмотренные варианты

1. **Всё на главном потоке** — проще, но блокировки UI и невозможность отменить вычисление.
2. **Worker с одним «живым» Manifold-инстансом и протоколом job/result** — UI не блокируется, отмена логическая
   (устаревший результат выбрасывается), состояние WASM переиспользуется.
3. **Пул воркеров** — параллелизм по деталям, но Manifold-инстансы дублируют память и усложняют код;
   выигрыш не оправдан на MVP.

## Решение

Вариант 2.

- `src/workers/geometry.worker.ts`: инициализирует Manifold один раз, слушает `postMessage`.
- Протокол (`src/workers/contracts.ts`):
  - запрос: `{ type: 'build', jobId, payload: BuildRequest }`;
  - ответ: `{ type: 'result', jobId, parts: TransferablePart[], stats, warnings }`;
  - ошибка: `{ type: 'error', jobId, message }`;
  - прогресс: `{ type: 'progress', jobId, stage, ratio }` (грубый, по этапам).
- Отмена: `jobId` монотонно растёт; клиент хранит последний актуальный id и **игнорирует** ответы с меньшим id.
  Внутри воркера длинные циклы проверяют `jobId` на предмет «я устарел» и прекращают работу (кооперативная отмена).
- Данные передаются `Transferable` (`Float32Array` вершин, `Uint32Array` индексов), чтобы не копировать меши.
- Дебаунс на UI-стороне: 150 мс для числовых полей, немедленный пересчёт для дискретных действий.
- Кэш: контуры листьев кэшируются по `docHash` (не пересчитываются при изменении настроек),
  результаты по деталям — по ключу «параметры листа + порядок + допуск» (M7).

## Последствия

- UI остаётся отзывчивым, устаревшие расчёты не «мигают» на экране.
- Один воркер = один экземпляр WASM, предсказуемая память.
- Ошибки воркера изолированы: в UI показывается сообщение, приложение не падает.
- Тестировать ядро можно без воркера (чистые функции), воркер тестируется интеграционно (M7).

## Когда пересматривать

Если время пересчёта станет больше ~1 с на типичных файлах — ввести пул воркеров по деталям и
инкрементальный пересчёт только изменившихся листьев.
