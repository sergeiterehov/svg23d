# План работ — svg23d

> Актуально на 2026-11-04. При возврате к проекту читать сверху вниз: статус → архитектура → текущий этап.
> Архитектурные решения и причины — в `docs/adr/`.

## 1. Цель

Превратить плоский SVG (нарисованный в векторном редакторе, без растра) в печатную 3D-модель:

- SVG разбирается на дерево элементов с сохранением группировки `<g>` и порядка отрисовки;
- каждому элементу/группе задаётся диапазон высот `zFrom..zTo` (мм);
- элементы верхних слоёв **вырезают** свой объём из нижних, с настраиваемым допуском (мм на сторону) —
  чтобы детали после печати совмещались;
- снятие фасок сверху/снизу (45°, размер в мм) на уровне элементов;
- экспорт в 3MF (мультиобъект + цвета; Bambu Studio — целевой потребитель) и бинарный STL.

## 3. Архитектура (кратко)

Три слоя, разделённые по зависимостям:

1. **Ядро** — `src/core/**`: чистый TypeScript, без React. Разбор SVG, 2D-геометрия, солвер, экспорт.
   Тестируется в vitest. Импортируется через алиас `@core/*`.
2. **Геометрический воркер** — `src/workers/**`: Manifold (WASM) в Web Worker, протокол job/result,
   transferable-буферы, отмена устаревших задач.
3. **UI** — `src/app/**` (React 19 + zustand + Tailwind) и `src/viewer/**` (three.js).

Ключевое правило: `src/core` не импортирует ничего из `src/app` и `src/viewer`.

## 4. Конвейер данных

1. Файл → санитизация (удаление `script`, `foreignObject`, внешних ссылок) → `DOMParser`.
2. `extractTree` — обход DOM: накопление аффинных матриц, разрешение стилей (presentation attributes,
   `style`, CSS-каскад), имена из `id` / `inkscape:label` / `data-name`, предупреждения о неподдерживаемом.
3. `flatten` — `path` (все команды, включая дуги) + `rect/circle/ellipse/polygon/polyline/line/use`
   → адаптивное разбиение кривых (flatness ≈ 0.02 мм) → подпути с флагом «замкнут/открыт».
4. `stroke` — обводка превращается в область (прямоугольник на сегмент + диск в вершину + колпак),
   выдаётся отдельным элементом `<id>#stroke` (ADR-0014).
5. `mask` — покрытие маски считается по яркости содержимого и применяется в солвере как
   `∩ include − exclude` (ADR-0015).
6. `units` — матрица «единицы SVG → мм»: масштаб считается по **bbox содержимого** (объединение bbox всех
   фигур), а не по `viewBox`, поэтому «размер модели 200 мм» даёт реальные 200 мм заготовки;
   режим `max` — по бо́льшей стороне (по умолчанию), также доступны `width` и `height`;
   инверсия Y, начало координат — левый нижний угол содержимого.
5. `section` — `CrossSection.ofPolygons(subpaths, fillRule)`: снимает самопересечения, дырки, ориентацию.
6. `extrude` — `CrossSection.extrude(h)` → `Manifold` по диапазону листа.
7. `chamfer` — верх/низ, 45°, ступенчатая тесселяция (шаг 0.05 мм): серия `offset(-delta)` + `extrude`, union.
8. `cutter` — «призрак» верхнего элемента: те же контуры с `offset(+clearance)` и те же фаски.
9. `buildParts` — листья в глобальном paint order; лист вычитает из себя всех более высоких листьев
   **других** деталей (отсечение по bbox XY и по Z); внутри детали — только union.
10. Результат → `MeshGL` (`vertProperties` / `triVerts`) → three.js и экспорт.

## 5. Модель данных

- `SvgDocNode { id, tag, kind: 'group'|'shape', name, fill, fillRule, opacity, hidden, children, subpaths, bbox, warnings }`
- `NodeSettings { zFrom?, zTo?, clearance?, chamferTop?, chamferBottom?, isPart?, hidden?, colorOverride?, enabled? }`
- `Project { version, fileName, doc, settings: Record<nodeId, NodeSettings>, global: GlobalSettings }`
- `ResolvedLeaf { id, partId, order, contours, fillRule, color, zFrom, zTo, clearance, chamferTop, chamferBottom }`

Разрешение настроек: ближайшее явно заданное значение у предка; иначе значение из `global`.
В UI показывается бейдж «наследуется / переопределено».

## 7. Как проверяем

- `npm run build`, `npm test`, `npm run lint` на каждом этапе.
- Геометрические инварианты (vitest, через `manifold.volume()` / `boundingBox()`):
  - квадрат 100×100, экструзия 2 мм → 20 000 мм³ ±0.1 %;
  - с фаской 1 мм → ≈19 800 мм³ ±1 %;
  - `offset(+d)` увеличивает площадь на ≈ `perimeter × d` (±2 %);
  - гнездо под элемент = площадь листа + `clearance × perimeter`.
- Golden-тест на `samples/html5.svg`: число контуров, суммарная площадь, bbox, объём листа.
- Обводка: площадь кольца = периметр×ширина − скругления; квадрат 10×10 с обводкой 2 → ≈ 79.14 мм².
- Экспорт: STL — размер = `84 + 50 × triangles`; 3MF — распаковать и сверить XML и число треугольников.
- Ручная проверка: 3MF → Bambu Studio.
## 8. Вне MVP (сознательно)

STEP-экспорт, `clipPath` / `mask` / фильтры как геометрия, текст, `stroke-dasharray`, растровые `image`,
базовая подложка, авто-раскладка на столе, точная лофт-фаска, редактирование геометрии мышью.

## 9. Риски

| Риск | Смягчение |
| --- | --- |
| Фаска ступенчатая (0.05 мм) | На печати неразличима; апгрейд на лофт-меш при требовании CAD-точности |
| Coplanar-грани в булевых операциях | Сдвиг границ на 1e-4 мм; тесты на объём |
| Совместимость 3MF с Bambu Studio | Ранняя проверка в M6, сверка с эталонным 3MF из Bambu |
| Производительность при десятках листьев | bbox-отсечение, кэш сечений, воркер, отмена задач |
| Порядок дерева влияет на геометрию | Явная индикация приоритета в дереве и пояснение в UI |
